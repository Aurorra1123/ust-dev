# ADM-001 ~ ADM-004 管理员端业务域重组验证

## 变更目标

- 将管理员端一级导航从旧的技术模块视角，调整为真实业务域视角。
- 将原资源工作区拆成“体育场馆”和“学术空间”两个独立入口。
- 为学术空间补齐按 `E1 / E2 / E3 / E4 ...` 组织资源的前端分组能力。
- 将规则工作区从一级导航下线，但继续保留后端规则能力与既有 ADR 决策。

## 实施摘要

- 管理员一级模块现已调整为：
  - `运营总揽`
  - `体育场馆`
  - `学术空间`
  - `活动管理`
  - `通知发布`
  - `工单维修`
- 一级导航中不再暴露旧的 `资源工作区` 与 `规则工作区` 入口。
- 现有 `ResourcesWorkspace` 已收口为共享底座，并新增两个前端壳层：
  - `SportsVenuesWorkspace`
  - `AcademicSpacesWorkspace`
- 体育场馆页现在只展示和管理 `sports_facility` 资源。
- 学术空间页现在只展示和管理 `academic_space` 资源。
- 学术空间页已增加按资源 `code` 前缀分组的区域切换：
  - 识别 `E1`、`E2`、`E3`、`E4` 等前缀
  - 不符合规则的资源进入 `未分区 / Ungrouped`
- 右侧资源创建表单在业务域页面中会锁定资源类型，不再重新暴露跨域切换。
- 运营总揽页的快捷入口、统计卡和步骤说明已同步到新的业务域结构。

## ADR 对齐

- 本轮实现沿用既有决策：
  - `docs/adr/0015-admin-workspace-split-by-business-domain.md`
- 本轮没有新增 ADR，因为当前实现没有超出既有重组边界：
  - 只改前端信息架构与页面组织
  - 不改 API、数据库或规则后端能力

## 本地校验

- `pnpm --filter web lint`
- `pnpm --filter web typecheck`
- `pnpm --filter web build`

## 结论

- `ADM-001` 已闭环：管理员端一级导航已切到新的业务域表达。
- `ADM-002` 已闭环：资源工作区已拆分为体育场馆与学术空间两个独立页面。
- `ADM-003` 已闭环：学术空间已支持按 `code` 前缀进行前端区域分组。
- `ADM-004` 已闭环：规则工作区已从一级导航下线，但相关后端能力与 ADR 仍保留。
