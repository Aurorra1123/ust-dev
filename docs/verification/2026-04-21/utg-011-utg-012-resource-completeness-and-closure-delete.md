# UTG-011 / UTG-012 资源完整性与关闭规则撤销验证

## 变更目标

- `UTG-011`：修复学术空间零单元资源在学生端表现为空白时间轴的问题，并补齐后台配置完整性提醒。
- `UTG-012`：为管理员补齐预约关闭规则的删除或撤销能力。

## 修复摘要

### UTG-011

- 后端公开资源边界已收口：
  - 学生端公开资源列表、公开资源详情和公开预约状态接口，当前只对“`active` 且至少存在一个资源单元”的资源开放。
  - 零单元资源不再继续暴露到学生侧主路径。
- 学术空间学生端已补零单元空状态：
  - 即使前端拿到零单元资源，也会显示明确说明，不再表现为近似空白的时间轴区域。
- 管理端资源工作区已补配置完整性提示：
  - 资源列表中零单元资源会显示“未配置单元”提示。
  - 资源详情中会明确说明：该资源当前不会在学生端形成可预约时间轴。

### UTG-012

- 后端已新增正式删除接口：
  - `DELETE /admin/resources/closures/:id`
- 写服务已补删除逻辑：
  - 不存在时返回 `resource-booking-closure-not-found`
  - 存在时执行物理删除并返回 `{ id }`
- 管理端资源工作区已补删除入口：
  - 每条关闭规则卡片现在都可执行“删除关闭规则”
  - 删除前有确认提示
  - 删除后会刷新资源列表和资源状态
  - 删除结果通过 `MutationState` 展示成功或失败反馈

## 相关决策

- 新增 ADR：
  - `docs/adr/0015-public-resource-must-have-units-before-student-exposure.md`
  - 明确“面向学生公开的资源必须先具备至少一个可预约单元”

## 本地校验

- `pnpm --filter api lint`
- `pnpm --filter api typecheck`
- `pnpm --filter web lint`
- `pnpm --filter web typecheck`
- `pnpm --filter api build`
- `pnpm --filter web build`

## 结论

- `UTG-011` 已闭环：零单元资源不再继续以“像坏了一样”的方式暴露给学生端，后台也能明确识别配置不完整资源。
- `UTG-012` 已闭环：关闭规则现在具备对称的删除路径，管理员不再需要通过数据库手工撤销错误配置。
- 本轮没有修改 demo seed 或线上数据库；对于线上“创新协作室”这类零单元资源，部署本轮代码后会自动从学生侧公开列表中收口，直到管理员补齐资源单元。
