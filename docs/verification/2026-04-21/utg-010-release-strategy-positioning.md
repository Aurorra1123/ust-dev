# UTG-010 放号规则前端定位收口验证

## 变更目标

- 降低管理员在资源工作区默认路径中面对“放号规则”的理解成本。
- 保留后端延迟开放能力，但不再把该能力与关闭规则并列放在主操作区。

## 实施摘要

- 资源工作区已把放号规则从默认主路径收进“高级调度设置”：
  - 若资源已有开放策略，则保持可见并显示策略数量、下次开放时间
  - 若资源没有开放策略，则默认只展示一张说明卡，由管理员主动展开
- 资源概况、状态标签和学生端提示文案已统一从“放号 / 待放号”调整为“开放策略 / 待开放”。
- 开放策略保存成功后，会同时刷新资源列表和资源状态查询，避免右侧状态面板仍停留在旧值。
- 关闭规则仍保留在默认主路径，符合当前 demo 更高频、更易解释的运营动作。

## 本地校验

- `pnpm --filter web lint`
- `pnpm --filter web typecheck`
- `pnpm --filter web build`

## 构建结果

- 本地 `web` 构建通过，最新产物为：
  - `dist/assets/index-mC6a_nw4.js`

## 结论

- 已形成明确产品结论：保留能力，但将前端暴露方式降级为高级调度设置。
- 当前界面不再让“放号规则”和“关闭规则”并列占据默认主路径，满足 `UTG-010` 的核心收口目标。
- 已存在的开放策略仍保持可见和可维护，没有因为简化展示而变成隐性状态，满足该项验收条件。
