# 0015 面向学生公开的资源必须先具备至少一个可预约单元

## 背景

第二轮用户测试 `UTG-011` 明确暴露出一个真实问题：

1. 某些资源已经被标记为 `active`，因此会出现在学生端资源列表中。
2. 但这类资源实际上没有任何 `ResourceUnit`，学生端时间轴没有可绘制的行，只会呈现接近空白的视图。

这说明“资源已启用”并不等于“资源已完成学生侧发布准备”。如果继续仅凭 `status=active` 对学生公开资源，会让未完成配置的资源直接进入学生主路径。

## 决策

从本轮起，面向学生公开的资源采用以下规则：

1. 资源必须同时满足：
   - `status === active`
   - 至少存在一个可预约资源单元 `units.length > 0`
2. 不满足上述条件的资源：
   - 不出现在学生端公开资源列表
   - 不通过学生端公开资源详情和预约状态接口暴露
3. 管理端仍然可以看到这些未完成配置的资源，并需要获得明确提示，提醒其当前不会形成学生侧预约视图。

## 明确不采用的方案

本轮明确不采用以下方案：

- 继续允许零单元资源直接暴露给学生端，再依赖学生自己理解“为什么没有时间轴”
- 仅在前端补一段空状态提示，但后端公开接口仍继续发布不完整资源
- 为了这个问题新增一套独立的“发布完成度状态字段”

这些方案要么继续保留错误公开边界，要么只治表面，要么在当前需求下引入了不必要的数据模型扩展。

## 影响

正向影响：

- 学生端资源列表不再暴露“已公开但其实无法预约”的半成品资源
- 资源是否对学生可见的边界更清晰
- 管理员可以更早发现配置不完整的问题

需要注意的影响：

- `active` 现在只表示“资源在后台启用”，不再单独等同于“学生端一定可见”
- 如果未来业务需要“预发布资源”或更细粒度发布状态，再单独规划状态模型会更合理

## 后续动作

1. 学术空间学生端继续保留零单元资源的明确空状态，作为边界保护
2. 管理端资源工作区对零单元资源提供显式提醒
3. 若未来扩展其他面向学生公开的资源类型，沿用同一条“先有单元，再公开”的原则
