# 0016 管理员首页收口为轻量入口页并恢复独立规则中心

## 背景

2026-04-21 的管理员前端重组已经完成了体育场馆 / 学术空间的业务域拆分，但后续继续复盘后，出现了两个新的结论：

1. `运营总揽` 仍然过重。首页同时承担统计、入口、说明、步骤和最新对象快照，信息密度偏高。
2. 将规则栏目完全从一级导航移除并不理想。规则能力虽然低频，但它仍然属于系统需要保留和可说明的正式能力；真正的问题不在“规则必须消失”，而在“规则页和资源页都混入了过多、过杂的规则控制内容”。

## 决策

本项目对管理员首页和规则能力的当前阶段处理方式明确如下：

1. `运营总揽` 收口为轻量入口页。
2. 运营总揽只保留：
   - 一行标题 + 一句说明
   - 5 个大按钮卡片
   - 3 个待处理数字卡
3. 运营总揽不再保留统计总览、步骤说明、对象快照等重内容区块。
4. 恢复独立的 `规则配置` 一级栏目。
5. 体育场馆页与学术空间页不再显式承担规则配置职责，只保留资源与资源单元维护能力。
6. 规则配置页按业务域拆为：
   - 学术空间规则
   - 体育场馆规则
7. 规则配置页采用简化结构，不再保留第三列概览/说明面板。

## 与 0015 的关系

本 ADR 保留 `0015-admin-workspace-split-by-business-domain.md` 中以下结论：

- 体育场馆与学术空间继续作为两个独立业务域存在
- 学术空间继续按 `code` 前缀分组
- 活动、通知、工单维持既有业务域结构

本 ADR 明确覆盖 `0015` 中以下一条阶段性结论：

- “规则工作区从管理员一级导航中下线”

也就是说，`0015` 的“资源业务域拆分”仍然成立，但“规则栏目完全下线”不再作为当前生效决策。

## 明确不采用的方案

本轮明确不采用以下做法：

- 继续把规则能力完全隐藏在一级导航之外
- 继续让体育、学术资源页同时承担规则控制职责
- 继续保留三栏式规则控制台
- 把运营总揽做成后台全景大屏

这些方案分别会导致规则能力不可见、页面职责混乱、规则页复杂度过高，或后台首页继续过载。

## 影响

正向影响：

- 管理员首页更像入口页，而不是报表页
- 资源页只做资源维护，职责更清晰
- 规则能力重新获得正式入口，但不再和资源页混在一起
- 学术和体育规则不再同屏混绑，管理员理解成本更低

需要注意的影响：

- 运营总揽中的大按钮卡片仍维持 5 个，不包含 `规则配置`；规则配置通过一级导航进入
- 若资源删除仍受规则绑定影响，资源页文案必须明确提示管理员去规则配置中解绑
- 当前实现若仍保留关闭规则、开放策略等能力，后续需要继续判断它们是进入规则中心，还是从管理员前端主路径中收口

## 后续动作

1. 新增正式方案文档，具体说明运营总揽和规则中心的简化目标。
2. 在开发计划中新增任务，分别覆盖：
   - 运营总揽轻量化
   - 恢复规则配置栏目
   - 规则中心按学术/体育拆分
3. 实施时优先保证资源页职责收口，不让规则再次回流到体育场馆 / 学术空间页面。
