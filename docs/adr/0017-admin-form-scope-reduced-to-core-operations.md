# ADR 0017: 管理员表单范围收口到核心操作

## 背景

管理员端已经完成一级模块重组，但页面内部的表单复杂度仍不均衡：

- 体育场馆 / 学术空间页虽然已经拆分，但仍需要明确长期边界应只保留资源维护表单。
- 规则配置页恢复后，如果继续沿用原有三栏控制台结构，复杂度仍然过高。
- 活动管理页已经做过一次简化，但首屏表单理解成本仍可继续下降。

同时，任务源要求系统保留可配置规则能力，因此不能通过“彻底删除规则能力”来换取表单简化。

## 决策

确认以下长期边界：

1. 体育场馆与学术空间页面只承担资源与资源单元维护，不再显式承载规则、关闭、开放策略和预约状态控制。
2. 规则能力保留在独立的 `规则配置` 栏目中，不再混入资源页主路径。
3. 规则配置页按学术空间 / 体育场馆分域组织，优先采用“两栏可操作页面”，不再回到三栏概览控制台。
4. 活动管理页继续保留当前主流程，但首屏只突出高频字段，低频配置维持折叠展开。
5. 管理员表单提示应以常驻说明为主，`placeholder` 只作为辅助，不再承担唯一解释责任。

## 影响

正面影响：

- 后台主路径的职责边界更清楚。
- 规则能力仍可演示、仍满足任务源的可配置要求。
- 资源页和活动页会更接近日常后台，而不是接口调试面板。

需要注意的影响：

- 资源删除若仍受规则绑定限制，页面文案必须明确引导去规则配置解绑。
- 资源单元编辑能力需要尽快补齐，否则资源页会继续处于“近似完整 CRUD”但并不完整的状态。
- 后续若需要扩充规则种类，应优先在规则配置中心内部扩展，而不是重新把规则入口塞回资源页。

## 后续动作

1. 继续实施 `ADM-006` 与 `ADM-007`，完成资源页去规则化和规则页分域简化。
2. 新增并实施 `ADM-008`，补齐资源页基础 CRUD 缺口和字段常驻说明。
3. 新增并实施 `ADM-009`，收口活动管理首屏表单与说明方式。
