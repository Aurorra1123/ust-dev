# 0012 前端日期格式化默认跟随当前语言设置

## 背景

`UTG-006` 的系统化审计中发现，前端多个学生页和后台工作区虽然已经接入中英文切换，但共享日期工具 `apps/web/src/lib/date.ts` 仍固定使用 `zh-CN`。

这会带来两个直接问题：

1. 英文模式下，日期时间仍会输出中文格式
2. 空值兜底文本会一直显示为“未设置”，导致界面继续出现中英混杂

如果在每个页面里手写一层 `localeText` 去包日期字符串，改动会分散到大量页面，后续也容易再次漏掉。

## 决策

本项目后续对前端日期格式化采用以下约束：

1. 共享日期工具默认跟随当前前端 `locale`
2. 若调用方有稳定格式需求，可显式传入 `locale`
3. 日期工具内的空值文案与日期格式使用同一套语言来源，不再拆开处理

## 明确不采用的方案

本轮明确不采用以下做法：

- 继续让 `date.ts` 固定输出 `zh-CN`
- 在每个页面手工写一层 `localeText(...formatDateTime(...))`
- 为中英文分别复制两套日期工具

这些方案的问题在于：

- 会把同一个基础问题拆散到多个页面重复修补
- 会继续制造“按钮是英文、日期还是中文”的割裂界面
- 会让后续新增页面更容易再次漏接语言切换

## 影响

正向影响：

- 核心学生页与后台工作区的日期显示会与当前界面语言保持一致
- “未设置 / Not set” 这类空值文案不再成为英文模式残留中文的来源
- 调用方仍可在需要时显式传入 `locale`，不会失去可控性

需要注意的影响：

- 共享日期工具现在依赖当前前端语言状态；若未来需要导出稳定格式，应显式传参而不是依赖默认值
- 业务数据正文、种子数据标题或用户输入内容不在本 ADR 约束范围内，允许保留其原始语言

## 后续动作

1. 后续新增界面若只需要跟随当前语言，优先复用共享日期工具默认行为
2. 若未来出现“导出 / 审计 / 固定格式报表”场景，应在调用点显式传入目标 `locale`
