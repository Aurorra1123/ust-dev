# ADR 0028：收紧 demo 认证暴露面并统一学术空间前后 5 分钟缓冲

## 状态

已接受

## 背景

当前终审前暴露出两类会被评委直接击穿的问题：

1. demo 账号安全边界不成立
   - Web 运行时 `config.js` 会把学生和管理员密码直接输出到前端
   - 前端源码仍内置默认 demo 密码
   - API 登录逻辑允许“任意已存在且激活的学生账号 + demo 学生密码”通过认证
2. 学术空间缓冲语义与题面不完全一致
   - 文档、迁移和答辩口径都写的是“前后各 5 分钟隐形缓冲”
   - 但学术预约创建链路实际写入的 `bufferBeforeMin` 仍为 `0`

这两个问题都不是措辞问题，而是会影响线上暴露面、自动化用例和现场答辩可信度的硬伤。

## 决策

### 1. 前端不再公开任何 demo 密码

- `config.js` 只保留前端真正需要的运行时配置，不再输出学生或管理员密码
- Web 登录页保留“快捷身份”入口，但只允许带入 demo 邮箱或角色，不再自动带入密码
- 前端源码中的静态 demo 密码一并移除，避免再次通过打包产物泄漏

### 2. demo 学生登录从“任意活跃学生”改为“显式白名单账号”

- API 不再接受“任意已存在且激活的学生账号 + demo 学生密码”
- 新增显式的 demo 学生邮箱白名单配置，默认至少包含 `DEMO_USER_EMAIL`
- judge / test / 演示环境如需保留 `partner1@campusbook.top`、`partner2@campusbook.top` 这类学生登录能力，必须通过白名单显式声明
- 管理员仍只允许 `DEMO_ADMIN_EMAIL + DEMO_ADMIN_PASSWORD`

### 3. 保留演示便利，但把凭据控制权放回部署环境

- judge / 本地环境可以继续通过环境变量提供 demo 账号密码
- 文档不再记录任何生产环境真实密码
- 生产环境需要立即旋转当前 demo / admin 密码，并同步部署变量

### 4. 学术空间缓冲统一为前后各 5 分钟

- 学术预约创建链路中的 `bufferBeforeMin` 与 `bufferAfterMin` 统一为 `5`
- 订单项、学术预约实体、订单详情返回值与验证用例统一按 `5/5` 对齐
- 与学术缓冲相关的 guardrail 要显式断言返回字段，不只验证 `11:04` 冲突和 `11:10` 放行

### 5. 历史数据按环境分开处理

- judge / 本地环境直接通过重置数据库和重新 seed 清掉旧的 `bufferBeforeMin = 0` 数据
- 对保留现有数据的环境，本轮不做自动 backfill，避免历史贴边预约在升级到 `5/5` 后直接触发数据库排斥约束
- 旧数据通过读取侧统一按 `5/5` 口径返回；如需彻底修正存量数据，必须先清理互相贴边的历史预约，再单独执行数据治理

## 不采纳的方案

### 方案 A：直接删除学生 demo 复用登录，只保留 `demo@campusbook.top`

不采纳。当前测试与演示链路已经依赖 `partner1/partner2` 学生登录，直接砍掉会破坏既有 guardrail 和爽约演示。

### 方案 B：继续把密码下发到前端，只做文案隐藏或字段混淆

不采纳。前端可读配置和打包产物对评委来说就是公开信息，隐藏文案不等于安全。

### 方案 C：只把学术空间冲突查询保持为 `±5`，不修落库字段

不采纳。评委只要看订单详情、数据库记录或排斥约束语义，就能指出实现与题面不一致。

## 影响

- 线上公开面不再直接暴露管理员和学生密码
- `partner1/partner2` 这类演示学生是否可登录，变成显式可控配置，而不是数据库里任何活跃学生都可登录
- 学术空间“前后各 5 分钟缓冲”会从口径、落库、接口返回到测试断言全部一致
- 认证、前端登录文案、judge 文档、自动化用例和部署变量都需要同步调整

## 执行步骤

1. 收口 demo 登录配置与 API 认证逻辑
2. 移除前端运行时和源码中的密码暴露
3. 为 judge / test 环境补齐白名单配置
4. 把学术预约 `bufferBeforeMin` 改为 `5`
5. 补认证与学术缓冲回归用例
6. 更新 judge / 部署文档，并在部署时旋转生产 demo 凭据

## 验收标准

- 公开站点的 `config.js` 和前端产物中不再出现 demo 密码
- 未进入白名单的活跃学生账号即使知道 demo 学生密码也必须返回 `401`
- 白名单内的演示学生账号仍能完成既有测试和演示链路
- 新建学术预约的 `bufferBeforeMin` / `bufferAfterMin` 都为 `5`
- 学术 `11:04` 冲突、`11:10` 放行和数据库层防重叠回归继续成立
