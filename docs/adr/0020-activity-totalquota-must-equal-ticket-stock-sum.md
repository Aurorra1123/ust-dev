# ADR 0020: 比赛整改阶段将活动 `totalQuota` 冻结为票种库存总和

## 背景

活动高并发库存整改已经被收口为独立工作包 `COMP-006`，但此前文档里对 `totalQuota` 的业务口径仍保留了两种解释：

- `totalQuota >= sum(ticket.stock)`
- `totalQuota == sum(ticket.stock)`

这种写法在文档阶段可以保留讨论空间，但一旦进入真实开发，就会直接造成以下分叉：

- 后端创建/更新活动时到底如何校验
- 前端活动表单如何提示额度关系
- 报名剩余量以活动总额度还是票种库存和为准
- 对账、库存恢复与异常回查如何定义“真相”

如果这条规则不先冻结，后续库存恢复、剩余容量展示、自动化测试和 judge 留证都会出现口径不一致的问题。

## 决策

比赛整改阶段确认以下规则：

1. 活动总额度统一定义为所有票种库存之和。
2. 系统强制要求：
   - `totalQuota == sum(ticket.stock)`
3. 创建或更新活动时，若 `totalQuota` 与票种库存总和不一致，保存必须失败。
4. 报名展示、库存对账、冷恢复和异常回查统一以这一口径计算。
5. 不再保留 `totalQuota >= sum(ticket.stock)` 的并行解释。

## 影响

正面影响：

- 后端、前端、测试和验证文档可围绕同一条规则实现与留证。
- 评委追问“总额度和票种库存冲突时以谁为准”时可以直接回答，不再含糊。
- 库存恢复与对账逻辑更简单，避免出现双真相。

需要注意的影响：

- 若后续想支持“总额度大于票种库存和”的更复杂业务，需要新增明确场景和单独设计，而不是复用当前比赛方案。
- 已有管理端表单和 seed 数据若存在不一致值，进入整改实现阶段后需要一并修正。

## 后续动作

1. 在 `COMP-006` 中按该规则实现活动创建/更新校验和剩余容量计算。
2. 在测试和 judge 留证中增加 `totalQuota` 与票种库存一致性的验证。
3. 在相关计划文档中移除双口径描述。
