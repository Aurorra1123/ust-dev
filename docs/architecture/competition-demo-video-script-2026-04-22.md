# 比赛演示视频最终动作表（证据核对版，2026-04-22）

## 1. 展示原则

本视频只展示仓库中已经实现、且能通过网页前端直接看到的功能链。主线不是页面巡礼，而是用连续录屏证明：学生端可以完成学术空间预约、体育场馆预约、活动报名与付费订单，系统会在网页上给出规则拦截、冲突拦截、状态变化和订单回写；教师端只用于展示规则配置入口和规则绑定证据。

以下内容不进入主视频展开：命令行、代码文件、数据库界面和工程内部能力页面。高并发内部实现、自动化验收和工程质量证据只适合在结尾或答辩材料中简要补充，不作为网页主录屏内容。

## 2. 录屏前人工确认

录制前必须先人工打开网页确认以下状态，避免演示数据被前一次录屏污染：

- `/spaces` 中存在可预约的“创新协作室 A”，且时间轴正常加载。
- 学术空间选择的成功预约时间段应位于未来，并且不与已有预约或关闭区间冲突。
- 学术空间规则拦截图段应选择“超过当前规则上限的预约时长”，不要写死具体日期。
- 学术空间冲突演示应在刚成功的同一单元订单附近选择与缓冲区重叠的时间段，不要写死具体时刻。
- `/sports` 中“羽毛球馆 A 区”存在可用 slot，并且“组合预订 / 双场联动场地”可选。
- `/activities` 中目标活动和付费票种仍可报名；当前学生账号没有该活动的有效报名记录。
- 如果当前账号已经报名活动，先换未报名账号或重置演示数据，不要在视频中硬演失败链路。

## 4. 可确认的页面、按钮、状态和资源名

以下名称来自当前仓库源码或 demo seed，可用于脚本和旁白：

- 页面路由：`/spaces`、`/sports`、`/activities`、`/orders`、`/orders/:orderId`、`/admin`
- 学术空间资源：`创新协作室`、`创新协作室 A`
- 体育设施资源：`羽毛球馆 A 区`、`A1 号场`、`A2 号场`、`双场联动场地`
- 活动与票种：`校园开放日 2026`、`普通入场名额`、`优先通行名额`
- 学生端按钮或链接：`提交预约`、`立即报名`、`查看订单详情`、`取消预约`、`模拟支付`、`重新预约`
- 教师端入口和页面：`教师工作台`、`规则配置`、`学术空间规则`、`体育场馆规则`
- 订单状态：`待确认`、`已确认`、`已取消`、`进行中`、`已结束`
- 支付状态：`待支付`、`已支付`、`支付失败`、`已退款`、`未发起`
- 后端可确认错误码：`rule-max-duration-exceeded`、`academic-reservation-conflict`、`sports-reservation-conflict`、`activity-already-registered`、`activity-sold-out`

## 5. 旁白精简版

### 开场

“我们展示的是一个校园服务门户，而不是单纯后台表单。学生在前台完成预约、抢票和订单操作；教师在后台维护规则和资源。”

### 学术空间

“学术空间采用连续时间预约。这里先选择一个超过规则上限的时间段，系统会拒绝；改为合法时间后订单创建成功；再选择与已有预约或缓冲区重叠的时间，系统继续拦截。最后取消订单，状态立即回写。”

### 体育设施

“体育场馆是另一套模型：它按 1 小时 slot 管理。组合预订会把双场联动场地作为一个整体展示，提交效果对用户可见。”

### 活动报名与支付

“活动报名不是一个普通提交按钮。付费票种会生成待支付订单，订单详情中能看到金额、支付状态和截止时间。点击模拟支付后，订单确认，支付记录变为已支付。”

### 订单中心

“学术空间、体育场馆、校园活动最终都进入统一订单视图。用户能回看资源、时间、状态，以及已取消记录。”

### 教师规则

“教师端的规则配置说明前台拦截不是写死的提示，而是绑定到资源的业务规则。主视频到这里停止，内部并发、部署和自动化验收证据留给答辩材料。”

## 6. 不建议录入主视频的内容

- 不安排订单移除动作，当前学生端确认的是取消订单。
- 不保证报名状态一定出现“排队中”，因为异步处理可能很快进入待确认或已确认。
- 不把命令行、数据库、代码文件或工程内部能力页面放进主视频。
- 不把工程质量证据包装成网页直接可证明的内容。
- 不在视频里现场修改教师端规则，避免影响后续学生端录屏数据。
- 不固定学术预约的具体时刻；录制时以“未来合法时间段”和“与刚成功订单冲突的时间段”为准。
- 不固定活动库存；录制前确认目标票种仍有余量且当前账号未报名。
