# 管理员运营总揽与规则中心简化方案（2026-04-22）

## 1. 文档目的

- 在已经完成“体育场馆 / 学术空间”拆分的基础上，继续收口管理员端的首页与规则配置体验。
- 纠正 2026-04-21 版本中“规则工作区从一级导航完全下线”的阶段性结论，避免当前文档继续误导后续实现。
- 为后续开发明确一条更稳定的后台信息架构：资源页只做资源维护，规则页只做规则配置，运营总揽只做轻量入口。

## 2. 当前问题

## 2.1 运营总揽仍然过重

当前 `OverviewWorkspace` 同时承担了：

- 统计总览
- 快速入口
- 结构说明
- 操作步骤说明
- 各业务域最新对象快照

结果是首页信息密度过高，管理员进入后台后仍然需要花时间“阅读后台”，而不是直接进入目标模块。

## 2.2 规则能力的去留出现了二次变化

2026-04-21 的信息架构方案中，规则栏目被从一级导航下线，理由是其技术味太重、干扰主路径。

但进一步复审后，这个结论存在两个问题：

1. 规则引擎属于任务源要求中的明确能力，不适合彻底从管理员前端消失。
2. 当前规则页之所以难用，不是因为“规则必须不存在”，而是因为：
   - 它过度控制台化
   - 体育与学术资源混在一起绑定
   - 资源页里也混入了大量规则/调度相关内容，职责不清

## 2.3 体育场馆 / 学术空间页仍然不够纯粹

虽然资源页已经按业务域拆开，但页面内部仍然保留了大量规则与调度逻辑，例如：

- 预约关闭规则
- 开放策略 / 高级调度
- 批量作用资源
- 资源预约状态与管理员取消预约

这会继续拉高资源页复杂度，也模糊“资源管理”和“规则管理”的边界。

## 3. 新的目标信息架构

本轮新的目标信息架构如下：

- 运营总揽
- 体育场馆
- 学术空间
- 规则配置
- 活动管理
- 通知发布
- 工单维修

与 2026-04-21 版本相比，主要变化有两点：

1. 恢复一个独立的 `规则配置` 栏目。
2. `运营总揽` 继续保留，但收口为轻量入口页，而不是概览大屏。

## 4. 运营总揽的简化目标

## 4.1 最终视觉结构

运营总揽只保留以下结构：

1. 一行标题 + 一句说明
2. 第一块：5 个大按钮卡片
3. 第二块：3 个待处理数字卡
4. 结束，不再继续堆快照和解释区块

## 4.2 第一块：5 个大按钮卡片

保留以下 5 个高频业务域入口：

- 体育场馆
- 学术空间
- 活动管理
- 通知发布
- 工单维修

这里刻意不把 `规则配置` 放进首页的主按钮区，原因是：

- 规则配置不是管理员日常最高频动作
- 恢复一级导航后，管理员已经可以直接从导航进入规则配置
- 首页继续塞入第 6 张按钮卡，反而会破坏“轻量入口页”的目标

换句话说：

- `规则配置` 是一级导航中的正式模块
- 但不占用 `运营总揽` 的主入口卡位

## 4.3 第二块：3 个待处理数字卡

运营总揽只保留 3 个最有运营意义的待处理数字：

- 待处理工单数
- 草稿通知数
- 未配置单元资源数

这些指标的共同特点是：

- 会直接提示管理员“现在应该先去处理什么”
- 比“总数统计”更接近日常动作
- 不需要在首页展开详情

## 4.4 明确删除的内容

运营总揽中以下内容应直接删除：

- 顶部 6 张统计卡
- `HighlightPanel`
- `WorkspaceBadge`
- `StepList`
- 底部 5 张“当前对象快照”卡

删除理由如下：

- 与主按钮卡片信息重复
- 与待处理数字卡目标重复
- 更像汇报页，不像日常后台首页
- 会继续增加首屏决策负担

## 5. 规则配置中心的目标结构

## 5.1 页面定位

规则相关能力不再混在体育场馆或学术空间页面里，而是集中进入一个独立的 `规则配置` 栏目。

该栏目承担的职责是：

- 创建规则
- 编辑规则
- 启停规则
- 删除规则
- 将规则绑定到对应业务域资源

资源页不再承担这些职责。

## 5.2 页面层级

`规则配置` 栏目内部只保留两个二级切换：

- 学术空间规则
- 体育场馆规则

本轮不建议再加入“通用规则”第三类入口，原因是：

- 会重新把页面复杂度抬高
- 当前最强的用户心智就是“学术”和“体育”两条线
- 可以先把最清晰的分法落地，再决定是否需要通用域

## 5.3 简化后的页面结构

每个规则子页建议采用两栏结构：

- 左侧：规则列表
- 右侧：规则编辑器

不再保留第三列“规则概览 / 使用说明”面板。

也就是说，当前规则页里应删除：

- `RulesSummaryPanel`
- 规则总数 / 启用中 / 资源绑定数
- 使用说明文案块

## 5.4 规则与资源绑定方式

学术空间规则页只展示并绑定：

- `academic_space`

体育场馆规则页只展示并绑定：

- `sports_facility`

这样可以直接解决当前“体育和学术混在一起绑定”的问题。

## 5.5 页面复杂度控制原则

简化后的规则中心遵循以下原则：

1. 规则页只处理规则，不做资源概览。
2. 规则绑定只显示当前域资源，不混域。
3. 规则页不承担教育型说明功能，避免一边配置一边看教程。
4. 页面结构优先可操作，而不是“看起来像控制台”。

## 6. 体育场馆 / 学术空间页的职责收口

## 6.1 收口原则

体育场馆页和学术空间页应继续保留，但只做“资源维护”。

这两个页面不再显式承担规则控制职责。

## 6.2 应从资源页剥离的内容

应从体育场馆页和学术空间页中移出的内容包括：

- 预约关闭规则
- 开放策略 / 高级调度设置
- 批量作用资源
- 资源预约状态查询
- 管理员取消预约入口

这些能力要么进入新的规则配置中心，要么在当前阶段从管理员前端主路径中收口。

## 6.3 资源页的保留内容

资源页只保留：

- 资源列表
- 创建资源
- 编辑资源
- 启停 / 删除资源
- 创建资源单元
- 编辑资源单元
- 删除资源单元

换句话说，资源页目标是“资源与资源单元的基础增删改查”。

## 7. 为什么这版更稳

这版结构同时满足 4 个目标：

1. 运营总揽不再复杂。
2. 体育与学术资源页重新变纯粹。
3. 规则能力没有从系统里消失，仍能满足任务源对“规则可配置”的要求。
4. 规则页本身也不再把不同业务域混在一起。

## 8. 与旧方案的关系

本方案与 `docs/architecture/admin-frontend-restructure-plan-2026-04-21.md` 的关系如下：

- 继续保留的结论：
  - 体育场馆与学术空间拆分为两个独立入口
  - 学术空间按 `E1 / E2 / E3 / E4 ...` 分组
  - 活动管理、通知发布、工单维修保持原有实现
- 被本方案覆盖的结论：
  - “规则工作区从一级导航完全下线”
  - “运营总揽保留较重的结构说明与快照信息”

因此，2026-04-21 方案文档继续作为“资源按业务域拆分”的基线存在，但首页与规则策略以本方案为准。

## 9. 推荐实施顺序

### 第一步：简化运营总揽

- 删掉统计卡、说明块、步骤块、快照块
- 保留 5 个主入口卡片
- 保留 3 个待处理数字卡

### 第二步：恢复规则配置一级栏目

- 在管理员一级导航中恢复 `规则配置`
- 调整命名，避免继续使用“规则工作区”这种技术口吻

### 第三步：剥离资源页中的规则内容

- 从体育场馆页和学术空间页移出规则、调度、预约状态相关块
- 页面只保留资源与资源单元维护能力

### 第四步：重建简化版规则中心

- 规则配置页内部只保留“学术空间规则 / 体育场馆规则”
- 两栏布局
- 仅绑定当前域资源
- 删除第三列概览与说明

## 10. 验收标准

本方案落地后，应满足以下标准：

1. 运营总揽只保留：
   - 一行标题 + 一句说明
   - 5 个大按钮卡片
   - 3 个待处理数字卡
2. 运营总揽中不再出现统计总览、步骤说明、对象快照。
3. 管理员一级导航恢复 `规则配置` 栏目。
4. 体育场馆页和学术空间页不再显式展示规则、关闭规则、开放策略和预约状态控制。
5. 规则配置页内部按“学术空间 / 体育场馆”分开，不再在同一资源绑定列表里混排两类资源。
6. 规则能力继续存在，且仍可作为系统满足任务源要求的正式能力进行说明和演示。

## 11. 非目标

以下事项不属于本方案的直接交付：

- 重做规则引擎后端实现
- 新增更复杂的规则类型
- 重新定义规则表达式模型
- 在本轮引入“通用规则”第三分栏
- 让运营总揽重新承担系统全景展示页职责
