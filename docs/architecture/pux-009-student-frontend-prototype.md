# PUX-009 学生端前端原型需求稿

## 文档目的

将 2026-04-20 用户提供的校园预约平台草图描述整理为正式执行层文档，作为 `PUX-009` 的实现输入。

本稿关注学生端前端原型的信息架构、页面组成与页面间流程，不替代后续视觉设计稿、接口细化稿和浏览器验收记录。

## 需求概括

整套前端原型表达的是这样一条主流程：

1. 用户先进入系统入口页并完成登录或注册
2. 登录后进入首页
3. 从首页选择体育、学术或活动资源
4. 进入对应资源预约界面，查看可用时段并提交预约
5. 在订单详情或个人中心中查看预约状态、处理变更
6. 在取消记录页面中回看已取消预约的历史信息

## 页面范围

本轮前端原型至少覆盖以下页面：

- 入口页
- 学生首页
- 资源预约页
- 订单或预约详情页
- 我的订单或预约记录页
- 取消记录页

其中资源预约页以体育馆预约页为重点样例，但整体产品流程仍需保留体育、学术、活动三类入口。

## 页面需求

## 1. 入口页

入口页位于整个系统最上游，用于让用户进入平台。

页面结构要求：

- 左侧为较大的展示区域，用于放系统名称、宣传图、欢迎语或平台介绍信息
- 右侧为登录注册区域，用于放账号、邮箱、密码等输入框
- 登录区域内需要存在清晰可见的注册入口

页面作用要求：

- 让用户先完成身份进入
- 让用户明确这是校园预约平台的统一入口

## 2. 学生首页

学生首页是登录后的主门户页。

页面结构要求：

- 顶部存在较显眼的展示区域，可表现为轮播图、公告区或热门资源宣传区
- 展示区下方存在两个主操作按钮：
  - 一个明显用于进入预约流程
  - 一个用于跳转到个人相关内容
- 页面主功能区存在三个核心入口：
  - 体育
  - 学术
  - 活动

页面作用要求：

- 让用户从首页快速进入主要资源类别
- 让用户同时看到平台通知、活动宣传或热门资源信息

## 3. 资源预约页

资源预约页是用户进入具体资源类别后的预约工作区。

本轮重点样例为体育馆预约页。

页面结构要求：

- 左侧展示资源名称、场馆名称或资源基础信息
- 中间为按时间展开的表格、时间轴或等价时段视图
- 页面中需要明确展示不同时段的占用情况
- 页面旁边需要存在状态说明区，用于解释不同格子的状态含义

页面状态要求：

- 用户可以区分哪些时间可预约
- 用户可以区分哪些时间已被占用
- 用户可以区分哪些时间段正在进行中
- 用户可以选择合适时段并发起预约

页面作用要求：

- 让用户不依赖文字解释就能理解时段状态
- 让资源浏览和时段选择发生在同一页面内

## 4. 订单或预约详情页

用户完成预约后，需要进入订单或预约详情页查看结果。

页面结构要求：

- 页面上方存在总览区域，用于展示当前预约总体状态，例如进行中、已确认等
- 总览区域下方存在若干操作标签或按钮
- 操作区至少覆盖确认预约、重新预约、提醒或其他后续动作中的等价能力
- 页面主体需要展示预约类别、地点、时间等关键字段

页面作用要求：

- 让用户快速确认当前预约是否正确
- 让用户在详情页继续处理后续动作，而不是返回上游页面查找入口

## 5. 我的订单或预约记录页

该页面属于个人中心相关区域，承担统一查看预约状态的作用。

页面结构要求：

- 页面以列表为主，用于集中展示用户发起过的预约记录
- 每一条记录至少包含：
  - 日期
  - 类别
  - 资源
  - 状态

页面状态要求：

- 用户可以快速区分已确认的预约
- 用户可以快速区分正在进行中的预约
- 用户可以快速区分已结束的预约
- 用户可以快速区分已取消的预约

页面作用要求：

- 让个人订单和预约记录有统一收口位置
- 让用户不需要回到各业务页面分别查状态

## 6. 取消记录页

取消记录页用于承接已取消预约的历史信息。

页面结构要求：

- 页面以历史记录列表为主
- 每条记录至少包含：
  - 取消时间
  - 预约人
  - 费用、备注或等价补充信息

页面作用要求：

- 让用户回溯过去取消过的预约
- 为后续查询和管理提供稳定入口

## 页面间流程关系

前端原型需要形成以下闭环：

1. 用户从入口页登录进入平台
2. 用户在首页选择体育、学术或活动资源
3. 用户进入对应资源预约页面并选择时间
4. 用户提交预约后进入订单或预约详情页
5. 用户在个人订单页集中查看状态与变更
6. 用户在取消记录页查询历史取消信息

## 实现约束

本稿只记录当前前端原型需求，不在本文件中强行规定：

- 最终视觉样式
- 最终接口字段命名
- 是否所有页面都拆成独立路由
- 注册流程是否接真实后端

以上内容在实现阶段可根据现有代码结构进一步细化，但不得偏离本文件定义的页面范围与主流程。
