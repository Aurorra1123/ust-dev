# 管理员表单收口方案（2026-04-22）

## 1. 文档目的

- 在已经确认“运营总揽轻量化、规则配置独立恢复、体育场馆 / 学术空间按业务域拆分”的基础上，继续把管理员端的表单复杂度收口下来。
- 回答一个更具体的问题：当前哪些表单属于必要表单，哪些属于重复表单，哪些虽然不多但仍然缺少明确提示或缺少完整 CRUD。
- 为后续开发提供一版可以直接落任务的执行方案，而不是只停留在聊天结论里。

## 2. 当前判断

## 2.1 体育场馆 / 学术空间页目前不是“表单太多”，而是“表单不完整”

当前资源页已经明显收口，主要只剩两张核心表单：

- 新增资源
- 新增资源单元

这意味着它的主要问题不再是“表单数量过多”，而是：

1. 缺少编辑资源入口。
2. 资源单元编辑能力不完整。
3. 很多字段仍然主要依赖 `placeholder` 解释，管理员输入后提示就消失。

所以资源页的策略不应该是继续做减法，而是：

- 保持数量克制
- 补齐基础 CRUD
- 把字段说明做得更稳定

## 2.2 规则配置页存在真正的冗余表单与重复结构

当前规则页的复杂度主要来自 4 个问题：

1. 左侧“新规则”大卡片与中间“创建规则”表单是重复入口。
2. 页面采用三栏布局，第三列“概览 / 使用说明”并不直接服务配置操作。
3. 资源绑定区把体育场馆和学术空间混在同一个列表里。
4. 规则编辑器虽然字段不多，但页面组织方式像控制台，不像后台表单。

这里的策略应该是做明显减法：

- 删除重复创建入口
- 删除第三列概览
- 按业务域拆绑定资源

## 2.3 活动管理页不是错误，但首屏负担仍然偏高

当前活动管理已经做过一次收口：

- 默认首票支持自动生成
- 进阶设置默认折叠

但问题还在：

1. 关键字段解释仍然偏依赖表单内文案和 `placeholder`
2. 时间字段没有外置说明
3. “自定义首票”和“进阶设置”虽然合理，但仍然会让第一次使用的人感觉页面很多

因此活动页更适合做“轻量收口”，而不是结构性重写。

## 3. 收口原则

本轮采用 4 条原则：

1. 资源页只做资源与资源单元维护，不重新混入规则配置。
2. 规则页保留，但作为次级能力页存在，不再长得像三栏控制台。
3. 活动页保留现有主链路，只削减认知负担，不动核心票务逻辑。
4. 优先改前端结构和提示，不先扩大数据库与后端改造范围。

## 4. 目标结构

## 4.1 体育场馆 / 学术空间：保留少量但完整的基础表单

两个资源页统一收口为：

- 资源列表
- 创建资源
- 编辑资源
- 启停 / 删除资源
- 创建资源单元
- 编辑资源单元
- 删除资源单元

这意味着资源页只保留“资源基础增删改查”，不再承担：

- 关闭规则配置
- 开放策略配置
- 预约状态查看
- 管理员取消预约
- 规则绑定

### 字段说明策略

关键字段要从“仅靠 placeholder”改成“常驻说明 + placeholder 辅助”。

建议常驻说明的字段包括：

- 资源：`code`、`name`、`location`、`description`
- 资源单元：`code`、`name`、`unitType`、`availabilityMode`、`capacity`

## 4.2 规则配置：保留能力，但删除重复表单

规则配置页保留为独立一级栏目，但页面内部改为：

- 顶部业务域切换
  - 学术空间规则
  - 体育场馆规则
- 左侧规则列表
- 右侧规则编辑

应删除的内容：

- 左侧“新规则”大卡片
- 第三列 `RulesSummaryPanel`
- 混合体育 / 学术的全量资源绑定列表

### 规则页的创建入口

规则创建入口保留 1 个即可：

- 左侧列表上方一个轻量 `新建规则` 按钮

不要同时保留：

- 大卡片式“新规则”
- 中央区默认新建态大标题

### 规则绑定策略

- 学术空间规则只绑定 `academic_space`
- 体育场馆规则只绑定 `sports_facility`

### 规则名称策略

本轮先允许手填规则名称，但后续可以评估自动生成规则名，例如：

- `学术空间 · 最长预约 120 分钟`
- `体育场馆 · 最低信用分 80`

这一项不是本轮必须做的范围。

## 4.3 活动管理：保留主流程，收口首屏

活动管理这轮不做大改，只做轻量收口：

- 首屏只强调最常见字段：
  - 活动标题
  - 地点
  - 总额度
- 默认首票继续自动生成
- 自定义首票继续保留为可选展开
- 进阶设置继续保留为折叠区

### 活动表单的提示策略

要补常驻说明的字段包括：

- 总额度
- 售卖开始时间
- 售卖结束时间
- 活动开始时间
- 活动结束时间
- 票种价格

目标不是减少字段数量，而是减少“我不知道该怎么填”的时刻。

## 5. 开发拆分

本轮方案与现有开发计划的关系如下。

## 5.1 已有任务继续保留

- `ADM-005`
  - 运营总揽轻量化
- `ADM-006`
  - 从体育场馆 / 学术空间页剥离规则相关控制
- `ADM-007`
  - 规则配置页按学术 / 体育分域，并删掉三栏控制台冗余结构

## 5.2 新增任务

### `ADM-008`

为体育场馆 / 学术空间页补齐基础 CRUD 缺口，并把资源表单提示从 `placeholder` 升级为常驻说明。

关注点：

- 编辑资源
- 编辑资源单元
- 关键字段说明外置

### `ADM-009`

为活动管理页继续做轻量收口，不改业务链路，只强化字段说明和首屏理解成本控制。

关注点：

- 首屏高频字段更突出
- 时间和票务字段有常驻说明
- 自定义首票与进阶设置继续维持折叠式展开

## 6. 风险与边界

## 6.1 不能把规则能力一起做没

管理员主路径可以简化，但规则配置能力仍必须保留。原因是：

- 任务源要求系统具备可配置规则能力
- 后端规则引擎已经存在，不适合为了收口前端而回退成硬编码

## 6.2 资源删除报错必须对齐新的页面结构

如果资源仍然因为规则绑定而无法删除，报错文案必须明确引导：

- 请先到“规则配置”中解绑相关规则

否则管理员会感觉系统存在“隐藏限制”。

## 6.3 资源单元编辑不能长期处于灰区

当前资源页容易给人一种“已经是完整 CRUD”的错觉。如果本轮暂时不补资源单元编辑，也必须：

- 在计划中明确记录
- 在后续阶段尽快补齐

不建议长期维持“可新增、可删除、不可编辑”的半完成状态。

## 7. 验收口径

这轮表单收口完成后，应满足以下结果：

1. 资源页不再显式出现规则、调度、关闭和预约状态相关表单。
2. 规则页只保留一套创建入口，并按学术 / 体育分域绑定资源。
3. 规则页不再保留第三列概览和说明。
4. 资源页和活动页的关键字段不再只依赖 `placeholder` 提示。
5. 管理员第一次进入后台时，能明显感觉到“表单更少、边界更清楚、填写更容易理解”。
